# Plan: ast-grep as native-TS custom tools (global opencode plugin)

## Goal
Turn ast-grep into first-class opencode tools the model calls directly. Port the
behavior of oh-my-openagent's vendored ast-grep skill (`ast-grep 0.43.0`) to a
single self-contained TypeScript plugin — **no Python dependency** — with
automatic binary provisioning.

### Locked decisions (from discussion)
- **Execution:** native TS tools calling the `sg`/`ast-grep` binary directly.
- **Shape:** plugin that registers tools + auto-provisions the binary.
- **Location:** global — `~/.config/opencode/plugins/`.
- **Source of truth:** vendored omo copy (pinned `0.43.0`).

## Deliverable (single file)
**CREATE** `~/.config/opencode/plugins/ast-grep.ts` — auto-loaded by opencode
(files in `~/.config/opencode/plugins/` are discovered automatically; **no
`opencode.json` change needed**). Imports resolve via
`~/.config/opencode/node_modules/@opencode-ai/plugin` (SDK v1.17.8, ESM,
exports `tool` + `Plugin`).

Only `node:` builtins + `globalThis.fetch` are used (mirrors omo's
`sg-provisioner.ts`, which needs zero npm runtime deps). No `package.json`.

## Tools registered (4)
All via `tool({ description, args, execute })` from `@opencode-ai/plugin`.
Use the raw `args` shape opencode expects, e.g.
`args: { pattern: tool.schema.string(), ... }` (not `tool.schema.object(...)`).
`execute(args, ctx)` is async and uses `ctx.worktree`/`ctx.directory` as the
default path. Output = human-readable string returned to the model.

| Tool | Args | Semantics |
|---|---|---|
| `ast_grep_search` | `pattern`, `lang?`, `paths?=`.`.`, `globs?[]`, `context?`, `json?`, `force?` | validate unless `force` → `sg run -p … --json=compact` → format `file:line:col preview` |
| `ast_grep_replace` | `pattern`, `rewrite`, `lang?`, `paths?`, `globs?[]`, `apply?`, `force?` | validate both unless `force` → **two-pass**: pass1 `--json=compact` (dry-run preview), pass2 `--update-all` only if `apply` |
| `ast_grep_scan` | `paths?`, `config?`, `rule?`, `inline_rules?`, `report_style?`, `apply?` | validate mutually exclusive config/rule/inline rules → passthrough to `sg scan`; capture stdout/stderr; preserve scan-specific exit semantics |
| `ast_grep_validate` | `pattern`, `lang?` | offline hint check only — no binary call |

Return contract: validation hints → return message (don't throw); binary
missing after provision attempt → actionable error string; success → formatted
summary **including file count** (blast radius). Cap displayed matches/output
to avoid flooding context while still reporting total matches/files.

## File structure (sections inside `ast-grep.ts`)
1. **Imports:** `node:child_process`, `node:crypto`, `node:fs`/`fs/promises`,
   `node:path`, `node:zlib`, `node:os`; `{ tool, type Plugin } from "@opencode-ai/plugin"`.
2. **Constants:** `SG_PINNED_VERSION="0.43.0"`; `SG_RELEASE_ASSETS` — the 6
   slugs (`darwin-arm64/x64`, `linux-arm64/x64`, `win32-arm64/x64`) →
   `{ url, sha256 }` verbatim from omo `sg-manifest.ts`; `LANGUAGES` (25) +
   `LANG_ALIASES`.
3. **Slug helpers:** `normalizeRuntimePlatform/Arch`, `runtimeSlug`,
   `sgBinaryName` (unknown→`linux`, non-arm→`x64`).
4. **Resolver `findSgBinarySync`:** order = `OMO_AST_GREP_SG_PATH` →
   `<runtimeDir>/sg` → PATH. PATH order on Linux = `ast-grep` then `sg`
   (reversed elsewhere); any `sg` hit requires `--version` (5s) exit 0 **and**
   output contains substring `ast-grep` (case-insensitive) — defeats the
   `/usr/bin/sg` shadow-utils collision present in this sandbox.
5. **Zip extractor + `provisionSgBinary`:** hand-rolled central/local-header
   parser (`EOCD/LOCAL/CENTRAL` magic, `inflateRawSync` for deflate, store for
   method 0, no zip64); `fetch` (60s timeout) → verify **whole-zip sha256
   before extract** → pick `ast-grep`/`sg` basename → write
   `.sg-<8hex>.partial`, `chmod 0o755`, atomic `rename`. Target dir:
   `~/.config/opencode/runtime/ast-grep/<slug>/`.
6. **Provisioning trigger:** module-level `Map<string, Promise<string>>` keyed
   by target dir, not a plain `Set`. Background provisioning and tool-triggered
   fallback share the same in-flight promise to avoid duplicate downloads and
   avoid returning missing-binary while background work is still running.
   `event: async ({ event }) => { if (event.type !== "session.created") return; ... }`
   schedules `setTimeout(0).unref()` background provision (skip if binary
   already resolves). Each async `execute` re-resolves and, if null, `await`s
   `ensureProvisioned(targetDir)` before failing.
7. **Validator `validatePattern`:** verbatim port — backslash-escapes
   (`\w|\d|\s|\b`), `.*`/`.+` (with `(?<!$)` lookbehind), char-class `[a-z]`,
   alternation detector (strip quotes → `\w\s*\|\s*\w` → exclude `||`), and
   lang hints (python trailing colon w/ MULTILINE; JS/TS/TSX, Go, Rust
   incomplete decls). Hint messages verbatim. Order: anti-patterns →
   alternation → lang hints.
8. **`runSgRun`:** spawn via `node:child_process` async wrapper (300s
   timeout); for `sg run` only, **treat exit 0 and 1 as success**; ≥2 → error;
   parse `--json=compact` with truncation salvage. Keep a separate `runSgRaw`
   for `scan`, returning raw exit code/stdout/stderr because `sg scan` may use
   exit codes differently than `sg run`.
9. **The 4 `tool({...})` definitions.**
10. **Plugin export** exactly shaped as
    `export default (async () => ({ event: async ({ event }) => { ... }, tool: { ... } })) satisfies Plugin`.

## Must-not-drift rules (faithful port checklist)
- `sg run` exit **1 = no matches, not error** — only exit ≥2 is failure.
  Do not reuse this assumption for `sg scan`; test scan-specific behavior.
- Two-pass replace: never combine `--json` with `--update-all` (sg silently
  drops the latter). Pass1 `--json=compact`, pass2 `--update-all`.
- Preserve the helper's `--force` escape hatch for false-positive validation
  hints in search/replace.
- JSON fields read: `file`, `range.start.line`, `range.start.column`, `text`,
  `replacement` (defensive defaults; never read `lines`/`language`).
- Linux: prefer `ast-grep`; gate any `sg` with the `--version` probe.
- Validate before every search/replace; `validatePattern` regexes + messages
  copied verbatim.

2. **Real provisioning E2E** (network confirmed: GitHub returns 302): run the

   `~/.config/opencode/runtime/ast-grep/linux-x64/sg` exists and
   `--version` prints `ast-grep 0.43.0`.
3. **Round-trip smoke** on a temp TS fixture (`console.log(x)`):
   `search`→matches; `replace` dry-run→preview, no mutation; `replace apply`→
   mutated; re-`search`→0 matches. Confirms two-pass + exit-code mapping.
4. **Scan smoke:** run `ast_grep_scan` for no findings, findings, and invalid
   config/rule combinations to confirm scan-specific exit handling and argument
   validation.
5. **`validatePattern` parity:** node harness with a pattern table
   (`\w+`, `.*foo`, `[a-z]`, `a|b`, `def $F():`, `function $N`,
   `func $N`, `fn $N`) asserting hints equal the Python helper's output run
   as oracle (`python3 …/ast_grep_helper.py validate` on the same inputs).
6. **`/doctor`-style sanity:** confirm opencode loads the plugin with no
   config error after restart (no `opencode.json` edits required).

## Out of scope (explicitly)
- No SKILL.md / reference docs bundled (per shape decision).
- No package-manager cascade (brew/npm/cargo/pip) — GitHub-direct only, like
  omo's TS provisioner.
- No PATH mutation / `OMO_AST_GREP_SG_PATH` writing — re-resolve via
  runtimeDir at call time.
- Linux/WSL/macOS supported; Windows best-effort (slug map present).
